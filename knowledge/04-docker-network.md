# Docker 网络

## 是干什么的

Docker 网络是解决容器之间、容器和外界怎么通信的。容器默认有自己独立的网络命名空间，有自己的 IP，容器之间要通信、容器要访问外网、外网要访问容器，都要经过 Docker 的网络配置。

理解 Docker 网络就抓住两点：容器之间怎么互相找到，以及端口怎么映射到宿主机。

## 怎么工作

### bridge：默认模式

`docker run` 不指定网络时，容器就进默认的 bridge 网络。Docker 会建一个虚拟网桥，一般叫 docker0，给每个容器分配一个网段内的 IP，容器之间可以直接用 IP 通信，容器访问外网走 NAT。

默认 bridge 有个短板：容器之间只能用 IP 互相访问，不能用容器名解析。自己建一个 bridge 网络就能用容器名互相访问，推荐做法是每个项目建一个自己的网络。

### host：共用宿主机网络

`--network host` 让容器直接用宿主机的网络命名空间，没有自己的 IP，容器里监听的端口就是宿主机的端口。性能最好、配置最简单，但端口冲突要自己管，隔离性也最差，适合对性能敏感又不怕端口冲突的场景。

### none：没有网络

`--network none` 的容器没有任何网卡，只有 loopback。适合完全不需要网络的批处理任务，或者由外部工具手动配网络的特殊场景。

### 容器互联与端口映射

同一自定义网络里的容器可以用容器名互相访问，Docker 内置的 DNS 会把容器名解析成容器 IP。跨网络的容器默认不能直接通信，要连进同一个网络才行。

端口映射 `-p 宿主机端口:容器端口` 是把宿主机端口的流量转发到容器端口。只写 `-p 8080:80` 是监听所有地址，想只允许本机访问可以写 `-p 127.0.0.1:8080:80`。

## 动手例子

建一个自己的网络，跑两个容器互相访问：

```bash
docker network create app-net
docker run -d --name db --network app-net postgres
docker run -d --name web --network app-net -p 8080:80 nginx
docker exec -it web ping db
```

`docker network create app-net` 建网络；两个容器都连进 app-net 后，web 容器里 `ping db` 能通，用的就是容器名解析。默认 bridge 里这样 ping 是不通的。

看网络和容器 IP：

```bash
docker network ls
docker network inspect app-net
docker inspect web | grep IPAddress
```

`docker network ls` 列出所有网络；`inspect` 看网络里连了哪些容器、各自的 IP。

只允许本机访问的端口映射：

```bash
docker run -d --name admin -p 127.0.0.1:8081:80 nginx
```

这样只有本机能访问 8081 端口，局域网其他机器访问不到，适合管理后台这类不想暴露的服务。

## 常见坑

- **默认 bridge 里用容器名访问失败**：默认 bridge 没有内置 DNS，容器名解析不了。要么用 IP，要么建自定义网络，推荐后者。
- **端口映射后外网还是访问不到**：先看容器是不是真的在监听，`docker exec` 进去看进程和端口；再看宿主机防火墙有没有放行映射的端口；最后看是不是只映射到了 127.0.0.1。
- **容器 IP 变了，写死的配置失效**：容器重启后 IP 可能变，配置里写容器 IP 的做法不可靠。同一网络里用容器名，跨主机用服务发现或固定域名。
- **host 模式端口冲突**：两个 host 模式容器都想监听 80 端口，后启动的那个会起不来。host 模式下端口是宿主机全局的，启动前要确认端口没被占。
- **容器访问不了外网**：一般是宿主机 IP 转发没开或防火墙规则丢了。先在宿主机上确认能上网，再看容器里能不能解析域名，分清是 DNS 问题还是路由问题。
- **网络删不掉**：网络里还有容器连着就删不掉，先把容器停掉或断开网络，再删网络。
