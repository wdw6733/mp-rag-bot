# TCP/IP 网络基础

## 是干什么的

TCP/IP 是一组让不同设备互相通信的协议，互联网就是跑在这套协议上的。它解决三个问题：数据怎么寻址、怎么分片传输、丢了怎么办。平时说的上网、传文件、看视频，底层都是 TCP/IP 在工作。

常见的分层说法是四层：应用层、传输层、网络层、链路层。应用层是 HTTP、DNS 这些具体服务；传输层是 TCP 和 UDP；网络层是 IP，负责找路；链路层是以太网、Wi-Fi，负责在同一段链路上传输。

## 怎么工作

### IP 负责找路

每台设备有一个 IP 地址，例如 192.168.1.10。数据被切成 IP 包，每个包带源地址和目标地址，路由器按目标地址查路由表，一跳一跳转发过去。IP 本身不保证送到，也不保证顺序，丢了不管。

### TCP 负责可靠送达

TCP 在 IP 之上加了可靠性。发送前先三次握手建立连接：客户端发 SYN，服务端回 SYN+ACK，客户端再回 ACK，连接就建好了。传输时每个字节都有序号，收到一方回 ACK 确认；收不到 ACK 就重传；序号乱了就重排。断开时是四次挥手。

TCP 还有流量控制和拥塞控制：接收方窗口告诉发送方一次能收多少，网络堵了就放慢速度，避免越堵越慢。

### UDP 负责快

UDP 不建连接、不确认、不重传，包发出去就不管。优点是快、开销小，适合视频通话、游戏、DNS 查询这类丢一两个包也不影响的场景。需要可靠时，由应用层自己处理。

### DNS 把名字变成地址

人记 example.com，机器只认 IP。DNS 查询就是把域名翻译成 IP 地址。电脑先查本地缓存，没有就问配置的 DNS 服务器，一级一级问上去，直到拿到答案。

## 动手例子

看一台机器的地址和连通性：

```bash
ip addr show
ping -c 4 example.com
```

`ip addr show` 看本机 IP 和网卡状态；`ping` 发 ICMP 回显请求，通了会显示往返时间，`example.com` 能解析说明 DNS 也正常。

看 TCP 连接状态：

```bash
ss -tlnp
```

`-t` 是 TCP，`-l` 是监听中，`-n` 显示数字端口不解析成服务名，`-p` 显示是哪个进程在监听。

抓一个真实的握手过程（需要 root）：

```bash
tcpdump -i eth0 -n host 192.168.1.10 and port 80
```

然后从这台机器访问一次网页，就能看到 SYN、SYN+ACK、ACK 三个包。

## 常见坑

- **能 ping 通网关，ping 不通外网**：一般是 DNS 或默认路由问题。先 `ping 8.8.8.8` 试 IP 通不通，再 `ping example.com` 试域名，分清是路由问题还是 DNS 问题。
- **TCP 端口明明服务在跑，客户端连不上**：先看服务是不是只监听了 127.0.0.1，`ss -tlnp` 里看到 `127.0.0.1:8080` 就是只允许本机访问；要对外服务得监听 `0.0.0.0`。
- **把 UDP 当 TCP 用**：UDP 丢包是正常的，视频卡一下、DNS 查一次失败都可能只是丢包，重试一次就行，不要当成网络断了。
- **子网掩码配错**：192.168.1.10/24 和 192.168.1.10/16 看起来只差一个数字，能直接通信的范围完全不同。配地址时掩码和网关要一起核对。
- **MTU 太大导致大包过不去**：链路 MTU 一般是 1500 字节，包太大又被禁了分片就会丢。症状是小网站能开、大文件传一半卡住，这时要检查 MTU 设置。
