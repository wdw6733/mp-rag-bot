# Docker 入门

## 是干什么的

Docker 是把应用和它依赖的环境打包成镜像、用容器跑起来的工具。镜像是一个只读的模板，容器是镜像跑起来的实例。同一份镜像在开发机、测试机、生产机上跑出来的行为一致，解决了“在我机器上能跑”这类问题。

容器和虚拟机不一样。虚拟机是整台电脑模拟出来，连操作系统都要一份；容器是共用宿主机的操作系统内核，只隔离进程、文件系统和网络，启动快、占资源少。

## 怎么工作

### 镜像与容器

镜像由一层一层的文件叠加而成，每条 Dockerfile 指令产生一层。容器启动时在镜像最上面加一层可写层，容器里改文件、写日志都落在这层，删容器可写层就没了。想持久保存数据要用数据卷。

### Dockerfile

Dockerfile 是写镜像的配方，常见指令有：FROM 指定基础镜像，COPY 把文件拷进去，RUN 在构建时执行命令装依赖，EXPOSE 声明端口，CMD 指定容器启动时跑什么命令。

### 常用操作

容器生命周期就几步：拉镜像、跑起来、看日志、停掉、删掉。镜像不用了也可以删掉省磁盘。

## 动手例子

跑一个 Nginx 看效果：

```bash
docker run -d --name web -p 8080:80 nginx
```

`-d` 是后台运行，`--name web` 给容器起名字，`-p 8080:80` 把宿主机 8080 端口映射到容器 80 端口。跑起来后访问 `http://192.168.1.10:8080` 就能看到 Nginx 欢迎页。

看容器状态和日志：

```bash
docker ps
docker logs web
docker exec -it web sh
```

`docker ps` 看正在跑的容器；`docker logs web` 看输出；`docker exec -it web sh` 进容器里交互操作，排查问题时最常用。

写一个最小的 Dockerfile：

```dockerfile
FROM nginx
COPY index.html /usr/share/nginx/html/index.html
```

构建并运行：

```bash
docker build -t my-web .
docker run -d -p 8080:80 my-web
```

`docker build -t my-web .` 的 `.` 是构建上下文，也就是 Dockerfile 所在的目录；`-t` 是给镜像打标签。

停掉并清理：

```bash
docker stop web
docker rm web
docker rmi my-web
```

## 常见坑

- **容器里写的数据随容器删除而消失**：日志、数据库文件写在容器可写层，`docker rm` 就没了。需要保留的数据一定要挂数据卷，例如 `-v /data/db:/var/lib/postgresql/data`。
- **镜像越攒越大**：每条 RUN 指令都是一层，构建时下载的安装包、缓存不清理都会留在镜像里。构建完顺手删缓存，镜像能小很多。
- **容器里进程退出容器就停**：容器只活在前台主进程里，主进程退了容器就退出。如果 CMD 写的是后台启动脚本，容器会立刻退出，要让主进程一直在前台跑。
- **端口映射写反了**：`-p 8080:80` 是宿主机在前、容器在后，写成 `-p 80:8080` 就会把宿主机 80 端口映射到容器 8080 端口，访问不到服务时先检查这个顺序。
- **用 latest 标签当版本管理**：latest 随时会变，出了问题不知道当时跑的是哪个版本。生产环境给镜像打明确的版本号标签，例如 `my-web:1.0.0`。
- **容器里跑 root 还挂了宿主机目录**：容器默认是 root，挂了宿主机目录就有写宿主机文件的权限。能用普通用户跑就用普通用户，挂目录时只给必要的读写权限。
